# 糖尿病视网膜病变平台前端改造方案

本 README 合并了此前两份改造方案，并整理成三项可分工的实施任务。

> **当前状态：** 本仓库现有代码仍是 Vue 2 / Vue CLI 乳腺癌前端原型。本文件描述后续改造方案；提交本文件不会自动把现有页面变成糖尿病平台，也不代表已有真实 AI、后端或临床验证。

## 项目目标

以现有前端为基础，改造成糖尿病视网膜病变（DR）筛查与随访平台的比赛演示版。先把界面和业务流程做通，默认使用合成演示病例；只有登录、多人数据共享、影像上传、真实推理等需求确实出现时，才开发对应的最小后端。

核心流程：

**选择患者 → 确认右眼/左眼 → 采集或选择眼底图 → 质控 → 展示 AI 草稿或转人工状态 → 医生审核签发 → 创建转诊/复查任务 → 患者查看已签发报告。**

平台按比赛方案服务四类角色：患者、基层筛查人员、眼科医生和区域管理人员。它是 DR 专项平台，不是泛化的血糖、饮食或运动管理应用。

## 页面规划

| 页面 | 主要内容 |
|---|---|
| 工作台 | 按演示角色显示待采集、待审核和待随访任务 |
| 患者档案 | 演示患者编号、所属机构、左右眼检查记录和时间线 |
| 筛查采集 | 核对患者与眼别，选择眼底图，登记设备和检查时间 |
| 质控结果 | 显示通过、需重拍、不可判读、资料缺失等状态与原因 |
| 医生审核 | 查看图像和结构化证据，接受、修改或退回 AI 草稿并签发 |
| 报告详情 | 显示医生签发内容、眼别、时间、来源和版本 |
| 转诊与随访 | 显示待联系、已提醒、已预约、已完成、逾期等任务状态 |
| 患者服务页 | 查看已签发报告、已确认计划和提醒；不能看未签发草稿 |
| 区域看板 | 按机构汇总筛查、质控、待审核和随访进度，不展示虚构准确率 |

演示版可以在同一 Vue 项目中用角色切换展示不同工作台；该切换只是演示交互，不是真实登录或权限系统。患者端没有经验证的眼底成像附件时，只提供问卷、提醒、报告查看和健康教育，不运行眼底影像诊断模型。

## 前端设计和数据约定

- 将粉色乳腺癌主题换成深青绿、蓝灰和浅色背景。风险、待办、离线状态要同时显示文字和图标，不能只靠颜色区分。
- 清除癌症页面、图标、图片、固定风险分、治疗建议、虚构医生问答和无来源的准确率/疗效数字。
- 每次检查按“患者—眼别—时间”组织，清楚记录患者编号、检查编号、右眼/左眼、采集时间、机构、设备和数据来源。
- 分别表示资料缺失、影像低质、数据过期、设备未知和服务故障；不补造数据，不把左右眼合并成一个眼级结论。
- AI 草稿和医生签发结果必须一眼可区分；报告签发后才进入患者页和转诊/复查任务。
- 比赛版 AI、质控和区域统计都用明确标记的模拟数据，不冒充真实推理或已验证结果。
- 公开 GitHub 仓库只放源码与合成数据，不放真实患者信息、眼底影像、密钥或账号凭据。

## 三项实施任务

### 任务一：前端底座、主题、路由和共用数据

**要做的工作**

1. 清理乳腺癌标题、菜单、图片、演示数据和业务路由，保留现有 Vue/Element UI 后台外壳和通用组件。
2. 更新产品名称、登录后首页、主题变量和导航。
3. 建立工作台、患者档案、筛查采集、医生审核、转诊随访、患者服务和区域看板的路由。
4. 统一患者、检查、眼别、影像、AI 草稿、签发报告和随访任务的演示数据结构。
5. 建立共用组件：患者信息栏、左右眼切换、图像预览、来源/设备标签、质控状态、审核记录、检查时间线和任务状态。
6. 创建集中管理的 DR 合成数据和 mock 服务，不把模拟数据继续写在页面组件里。

**主要改动位置**

- src/settings.js：产品名称和浏览器标题。
- src/router/index.js：登录后首页和根路径。
- src/router/modules/prediction.js：清理旧预测菜单；建议改为 DR 专用路由模块。
- src/styles/variables.scss：主题颜色。
- src/components/dr/：共用 DR 组件。
- src/mock/dr/：模拟病例与 mock 服务。
- src/views/：新业务页面骨架。

**交付结果与完成标准**

新菜单可以进入所有规划页面；页面刷新和直接访问路由正常；全局已清除乳腺癌业务内容；统一模拟数据至少区分右眼、左眼及任务状态，供任务二、三复用。

### 任务二：筛查采集、质控和医生审核签发

**要做的工作**

1. 实现患者档案、检查列表和左右眼检查时间线。
2. 实现“确认患者 → 确认眼别 → 选择/导入眼底图 → 登记设备和时间 → 提交质控”的采集向导。
3. 展示质控通过、需重拍、严重不可判读、设备未知等结果，并说明原因和下一步。
4. 用合成数据展示病灶证据、ICDR 候选等级、可用/缺失模态和 AI 草稿状态。
5. 实现医生接受、修改、退回或签发；保留审核意见、修改原因、医生和签发时间。

**主要改动位置**

- 新建 src/views/patients/、src/views/screening/、src/views/review/。
- 将 src/views/prediction/input/index.vue 改为采集向导。
- 将 src/views/prediction/assess/index.vue 改为质控结果和 AI 草稿。
- 将 src/views/prediction/subtype/index.vue 改为眼别记录与影像证据。

**交付结果与完成标准**

从患者档案可以走到采集、质控、医生审核和签发；至少演示通过、重拍、需复核和医生修改签发四种状态；未确认患者/眼别不能提交；缺少 OCT 时只能显示未提供/未评估，不能显示已确认 DME；所有 AI 内容均标注为演示草稿。

### 任务三：签发报告、患者随访、区域看板及必要后端

**要做的工作**

1. 将原 advice 页面改为医生签发报告及已确认的转诊/复查计划。
2. 实现转诊和随访状态流转：待联系、已提醒、已预约、已完成、逾期/失访。
3. 实现患者服务页，只显示已签发报告和已确认计划，并提供提醒确认/随访反馈。
4. 实现区域演示看板，统计筛查、质控和随访任务；数字必须与合成病例一致。
5. 串通“医生签发 → 建立任务 → 患者查看/确认 → 区域状态更新”。
6. 默认用任务一的 mock 服务，不先开发完整后端。

**主要改动位置**

- 将 src/views/advice/index.vue 改为签发报告。
- 将 src/views/chat/index.vue 改为报告解释演示和联系医护入口，不保留固定医疗答复或虚构医生。
- 将 src/views/personal/ 改为患者档案/检查记录。
- 新建 src/views/followup/、src/views/patient/、src/views/region/。
- 新建 src/services/dr/ 作为 mock/API 适配层。

**交付结果与完成标准**

完整演示报告签发、任务创建、患者查看/确认和区域汇总；患者端看不到未签发内容；统计与同一批模拟数据一致。

#### 哪些情况才需要后端

| 需要做的事 | 比赛前端是否必须有后端 |
|---|---|
| 页面展示、按钮交互、演示状态流转 | 否，用合成数据和 mock 服务 |
| 跨浏览器/设备长期保存、多人登录和真实角色权限 | 是，增加账号、权限和持久化接口 |
| 上传或保存真实眼底影像 | 是，增加受控上传、权限校验和安全存储 |
| 调用真实眼底 AI 模型 | 是，增加推理服务接口，并返回模型版本、失败/拒识状态和结构化草稿 |
| 医生签发留痕、任务跨机构同步 | 是，增加签发、任务和审计服务 |
| 只有区域统计展示 | 演示时否；真实跨机构统计时需要后端汇总 |

如果确需后端，先只做前端无法完成的接口：患者/检查读取、影像上传、获取 AI 草稿、医生签发、任务更新和区域统计。FHIR、CQL、GraphRAG、模型训练和端侧 QNN 等服务不因架构图而自动加入，等对应功能真正需要时再接入。

## 执行顺序和协作方式

1. 先完成任务一，确定菜单、组件、病例字段和模拟服务接口。
2. 任务二、任务三在接口约定后并行制作页面；任务三以任务二的“已签发报告”数据为输入。
3. 最后用 3–5 个合成病例联调全流程，覆盖质控通过、需重拍、AI 不确定、医生修订签发和待随访。
4. 完成页面交付检查：没有乳腺癌残留；从采集到随访可以连续演示；所有演示数据有标识；不存在冒充真实模型、真实医生或真实患者数据的内容。

## 本地运行

在项目目录运行：

- 安装依赖：npm ci
- 启动开发环境：npm run dev
- 构建生产包：npm run build:prod

现有仓库包含前端页面和静态资源，不包含 DR 预测模型或后端服务。相关临床字段与转诊/复查规则需由合作临床团队确认；参考[2024 年基层糖尿病微血管疾病筛查共识](https://www.chinagp.net/CN/10.12114/j.issn.1007-9572.2024.0163)及[ADA 2026 视网膜筛查建议](https://diabetesjournals.org/care/article/49/Supplement_1/S261/163919/12-Retinopathy-Neuropathy-and-Foot-Care-Standards)。
