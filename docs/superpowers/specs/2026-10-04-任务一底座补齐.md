# 任务一底座补齐

用户已确认沿用当前主题，并要求落地补齐核查缺口。本次实施覆盖任务一的七类入口、共用数据、组件和模拟服务，不要求真实推理或临床签发。

## 实施设计

- 保留 Vue 2、Element UI、青绿色后台、微软雅黑和当前医疗照片登录页。
- 新建 DR 路由模块，提供工作台、患者档案、筛查采集、医生审核、转诊随访、患者服务、区域看板。旧链接保留隐藏重定向，菜单只显示新业务。
- 使用 src/mock/dr 的确定性合成数据：患者、检查、眼别、影像、AI 草稿、签发报告、随访任务，以及机构、设备、审核记录。所有对象带合成标记和稳定 ID，任务关联报告，逐眼结果单独记录。
- 建立纯 JavaScript 模拟仓库和 src/services/dr 服务层。页面共享同一个响应式仓库，全部模拟读写通过浏览器服务进行；根目录 HTTP mock 只提供初始 fixture 的只读调试接口，不能形成第二套可写运行状态。后续接 API 时应整体切换服务适配。
- 保存带版本的合成元数据到本地浏览器。不得保存 File、blob URL 或真实上传内容；新采集图片重新加载后提示需要重新选择。存储损坏或不可用时回退合成数据；所选病例仍可由 URL 的 patientId 和 examinationId 恢复。
- 校验路由上下文，患者与检查必须匹配。旧兼容数据模块只作为 facade，不再独立维护患者副本。改动经共享服务更新，工作台、档案和区域汇总一致。
- 共用组件放入 src/components/dr：患者栏、眼别切换、原图预览、来源/设备标签、质控状态、审核记录、检查时间线、任务状态。现有组件通过薄包装兼容。
- 页面内检查历史、任务和共识输出移入集中数据或选择器；不从当前等级减一生成历史。患者服务按当前 patientId 过滤，只返回该患者已签发合成报告及其确认任务，不返回其他患者记录或未签发草稿。
- 清理已经不再引用的旧乳腺业务图像及视频；保留通用组件与素材，更新 README 的实施状态。

## 实施顺序

1. 集中 fixtures、状态枚举、仓库、服务接口及关联验证。
2. 兼容数据 facade、路由上下文与七类菜单入口。
3. 共用组件、新页面骨架和既有页面的数据迁移。
4. 清理旧资源、记录字段和服务约定。
5. 运行关联、患者可见性、更新一致性和路由上下文测试；完成局部 ESLint、生产构建及浏览器桌面/手机、直达/刷新验证。

## 完成标准

七类入口均可进入，带病例上下文的 URL 可直达和刷新；左右眼与任务状态共用同一约定；页面不再构造业务病例、历史记录或任务；合成元数据关联完整，患者服务不出现未签发草稿；旧乳腺业务资源清除；既有登录轮换与未评估边界保留。
